# MVP output and trust contract

Finalized for implementation on 2026-10-11 under D38. No example below is an actual company result. Numerical financial values are rendered from code fact objects, never generated by the model.

## Run envelope

Code owns run ID, immutable validated inputs, source cutoff/retrieval timestamps, input/output schema versions, stages, errors, elapsed time, and counters. A run has one result per selected ticker and up to three total talking points. Partial successes remain visible. A failed lookup is not an unchanged company or a healthy business.

## Source and fact objects (code-owned)

Source: ID, ticker, URL, accession, form/exhibit, filing date, covered reporting period if established, retrieval timestamp, normalized-content hash. Release text preserves stable paragraph IDs for evidence lookup.

Fact: ID, metric/taxonomy concept, numeric value, unit, start/end dates, fiscal year/quarter, reporting basis, accession, derivation if any, current/comparison source references, and code-formatted display string. Primary baseline is same fiscal quarter a year earlier; QoQ only when comparable. Each delta records its formula and comparability result. Missing/noncomparable values remain explicit.

Do not use a generic 90-day filter: issuer calendars include 12-, 13-, 14-, 16-, or 17-week quarters. Select by fiscal context, dates, accession and metric basis. Derive discrete cash-flow periods only from comparable additive cumulative values; never subtract cumulative EPS. Do not equate GAAP and adjusted results or reported and managed bank revenue. Zero/negative baselines require an explicit comparison policy; percentage growth is unavailable by default. Source-precision-aware matching allows legitimate rounding, not an arbitrary broad tolerance.

## Holding result, in review order

1. Coverage: company, period, release date, source cutoff, newest covered fact date, missing data, and source links.
2. Financial changes and key updates: up to three material supported findings; code facts display values and deltas. Narrative is current-release commentary, not a demonstrated change unless comparative evidence exists.
3. Research focus: at most two actual investigated questions, relevance to profile fields, tool-returned evidence IDs, answer status (`supported` or `unresolved`), and missing evidence.
4. Why it matters: short evidence-linked interpretation with relevant profile fields, distinguishable from reported facts.
5. Watch next: at most two concrete questions, original evidence baseline, observable signal, why it matters, and qualitative strengthen/weaken conditions. No invented numeric trigger, probability, or autonomous monitoring promise.
6. Evidence and uncertainty: expandable exact excerpts, facts, trace and specific check labels; dropped content count and limitations. No forced unchanged section without a defined checked metric/baseline/threshold.

Management outlook is optional. For initial implementation omit quantitative guidance until a separate source-value validation path exists; quotes with forecast quantities are ineligible under the actual-fact-only verifier. Non-numeric management statements may be attributed with checked quotes. No independent forecast or target price.

## Model-owned structured draft

Strict fields: findings[], research_answers[], interpretations[], watch_items[], uncertainties[]. Empty arrays are valid; do not pad. Each item has a stable ID, referenced eligible fact IDs and/or tool-returned evidence IDs, and text. Interpretations and watch items also reference finding IDs and relevant profile fields. Research answers reference planned question IDs. Uncertainties describe supported gaps, not unsourced risk assertions. Stage-specific schemas restrict IDs to the current holding and run.

The model may use fact placeholders in text; code substitutes canonical formatted values. No free numerical company claims in prose. Evidence quote fields are exact source strings, never interpolated or corrected. Source dates and figures are rendered outside model prose. User-parameter labels come from validated input. This supports enforcing the rule without confusing profile horizon with company numbers.

## Deterministic verifier and dependency removal

- Verify referenced IDs belong to the holding, run and source snapshot.
- Require all displayed excerpts to match normalized source text (normalize whitespace only).
- Verify fact periods, units, definitions, source lineage and computed changes before eligibility.
- Reject unsupported free numerical claims; preserve original quotations only when numerical assertions can be matched to eligible actual facts with correct period/basis. Exclude numerical outlook until its verifier exists.
- Remove invalid items plus all dependent interpretations, watch items and talking points. Do not show a conclusion after dropping its supporting evidence.
- Build up to three run-level talking points only from surviving items; choose supported points in code without an additional unverified synthesis call.
- Counts: candidate items, removed items, dependency removals, shown items, and unavailable metrics. Use fixed denominators; distinguish dropped claims from missing input evidence.

Labels describe exact checks: Quote matched filing; Figure checked against SEC structured data; Interpretation. Never label the entire brief verified. Two issuer-provided formats are consistency checks, not independent corroboration.

Code checks cannot establish entailment, materiality, balanced selection or contextual usefulness. Human evaluations inspect whether evidence supports interpretations and watch items. Prompt controls alone are not proof.

## Illustrative one-holding screen

Inputs: Generate ongoing income / Medium term: 3–10 years / Low risk.

Coverage: [company], [fiscal period], release [date]. Evidence current through [date].
Financial changes: [code-rendered earnings comparison]; [code-rendered comparable cash-flow comparison].
Research focus: Does the release explain the cash-flow decline? Evidence checked: [actual matched paragraph IDs].
Finding: [supported explanation], or The retrieved release did not establish the cause.
Why it matters: Cash generation is relevant to the income goal; one observation does not establish a persistent pattern.
Watch next: Does comparable cash generation recover in the next reported period? Baseline: [fact IDs]. A repeat decline would warrant investigating persistence; recovery would weaken that concern.
Limit: This illustrates layout and dependency structure, not factual analysis or a forecast.

## Completion and failure

Successful: eligible supported findings or explicit insufficient-evidence outcome, completed bounded lookup record, checked dependencies, visible dates/limits. Never require a positive finding.
Recoverable per-holding states: source unavailable, insufficient comparable facts, no eligible release, analysis unavailable, could not verify. Preserve other results and immutable inputs. Model refusal, incomplete output, invalid schema and timeout cannot appear as completed analysis.

## Holding-rationale revision (D43)

This version is one company per run. Inputs add a required bounded holding_rationale enum: profitable_growth, dependable_income, business_resilience. Model output adds premise_assessment with matching rationale_id; supports/challenges/unresolved status; short headline; what_this_means; supported_parts/challenged_parts/unresolved_parts; next_decisive_evidence; and finding/fact references. Preserve the underlying evidence arrays for inspection. Assessment dependencies are checked and failed conclusions removed with an unresolved fallback. The status is an evidence assessment, not an investment action.

Primary UI should expose the user’s premise and its unresolved or challenged component instead of a report recap. Existing short table-label fidelity and numerical-free quote limits remain, and interpretation support still requires evaluation. Only one company is selected at a time; all five source adapters remain available.

## Visible assessment drivers (D44)

The default result must include a concise overall premise-assessment summary and up to three material earnings highlights explaining it. Present current code-owned numbers, units and eligible prior-period comparisons, plus a short rationale-specific implication. Numbers come from existing fact records; the model does not calculate or invent values. Qualify declaration-versus-payment and partial-cash-flow measures visibly. Preserve source references and calculation lineage on expansion. Selection must retain valid assessment/finding/fact dependencies; missing decisive evidence remains unresolved rather than a negative rating. The design preview demonstrates this presentation; automatic driver selection and application rendering remain pending. Historical rating movement requires saved compatible assessments and is outside this change.

## Qualitative support and gap semantics (D47)

Use existing evidence-linked findings to expose material management commentary or execution milestones explaining the financial takeaway. Attribute statements; keep agent implications separate. Up to two qualitative supporting points may accompany the three numerical drivers. Each explanation must have an appropriate supporting source passage; no generic durability caveat as a substitute for investigation. Distinguish future uncertainty, missing disclosure, conflicting evidence and incomplete agent retrieval. The last is an agent limitation and must not be presented as a company weakness. These requirements refine presentation and support evaluation; no new schema fields or live model results are claimed by this design revision.

## Context-specific three-part output (D48)

Render each material finding with its dependent interpretation and watch item as: What happened / What this means for your goals / What remains unanswered or watch next. Preserve fact and passage references, attributed statements and surviving dependency checks. Consider ticker, goal, holding rationale, holding period and risk tolerance in planning; relevance must follow a concrete mechanism rather than a restatement of the inputs. Horizon changes investigative emphasis; risk changes emphasis on adverse scenarios and tolerable uncertainty, not evidence strength. Missing inputs such as portfolio weights and prices preclude quantitative portfolio-impact or valuation claims.

Watch-next content should contain an answerable question, needed evidence and strengthening/weakening conditions. It can seed a future bounded follow-up agent, but UI copy must not imply that subsequent research or monitoring has executed. Test inputs individually for justified effects while holding sources and facts constant. Existing arrays can express the structure; coordinated prompt/rendering refinement and evaluation remain pending, rather than claiming a new implementation from this documentation change.

## Takeaway-driven financial selection (D52)

Primary full-report synthesis selects existing eligible fact/comparison IDs for the financial evidence supporting or qualifying its chosen context-specific takeaway. Rendering must resolve IDs to code-owned labels, values, units, periods and baseline figures; no model-authored arithmetic or invented quantitative relationships. Each selected row has a concrete link to a supported claim. Include material counterevidence where available, avoid a static metric grid and avoid numbers chosen merely for size. Existing finding/assessment references provide a starting point, but dedicated selected-row joining and render validation remain to be implemented. If no eligible measure supports the narrative, keep it qualitative or unresolved. Adaptive follow-up remains separate.

## Advisor holding-explanation alignment (D54)

Primary output reuses the selected evidence for one concise advisor discussion point instead of a forced three-talking-point list. All claims retain dependency and source checks; no separate model call is required merely for the discussion copy. Group takeaway, qualitative evidence, selected financial rows, unanswered/watch conditions and discussion point. Do not imply actual portfolio exposure, suitability or client goal progress. Revised full-source selection and rendering remain pending.


## Reported-first financial evidence policy (D87, 2026-10-12)

Prefer a directly reported figure, ratio or growth rate when its metric definition, fiscal period, comparison baseline, units and GAAP/non-GAAP basis match the research question. Do not routinely recalculate an already reported metric or require a second data source solely to certify the issuer's arithmetic. Validation means checking correct extraction, context and source references; it does not certify the issuer's accounts or the model's interpretation.

Use deterministic code only for a needed comparison or calculation not explicitly reported on the required basis, such as a cross-release margin change or a reconciled cash-flow bridge. Preserve input references, formula, period/basis checks and source precision. Do not subtract cumulative EPS or mix incompatible definitions. If the reported value and an existing derived value disagree beyond explainable rounding, expose the discrepancy and withhold the disputed comparison rather than silently substitute a value or average them.

Keep reported and derived provenance distinct: reported facts retain the exact source location and reporting basis; derived facts additionally retain their formula and input lineage. The model selects and interprets eligible evidence, without inventing numbers or performing unchecked arithmetic. Missing or incompatible evidence remains an explicit limitation.

Acceptance criteria: a matching reported metric is reused without redundant recomputation; a missing eligible comparison is calculated with traceable inputs; wrong-period/unit/basis extraction is rejected; reported precision is preserved; contradictory values are surfaced. These are requirements, not newly executed evaluation results.
