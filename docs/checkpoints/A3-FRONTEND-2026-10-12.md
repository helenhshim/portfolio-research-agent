# A3 V2 frontend checkpoint

2026-10-12 · D73 · Local implementation, not a released V2 or passed model evaluation.

## What changed

`/v2` uses the approved A3 system: local Geist/Geist Mono, eight type styles, token-only CSS, light mode, Q/A gutters, ruled tables, square controls and one highlighted fact. All twelve kit families and the three layouts exist. Entry is 06a, review/continuation is 06b, and 06c is an optional current-session layout. Desktop keeps the composer visible while inspecting the brief; mobile uses keyboard-accessible Thread/Brief tabs.

Reuse the frozen NVDA packet and existing V2 controller/verifier/financial/revision primitives. Numbers and calculations never come from generated values. A saved, explicitly authored reference goes through core reference checks; it is not actual model output or semantic certification. Citation clicks open/focus their source paragraph. Complete cash components use a disclosure rather than exceeding three main evidence rows.

A bounded NDJSON route at `/api/v2/research` uses the existing direct-provider stack. It validates identity/question/history, rejects identified sensitive patterns before dispatch, uses one concurrent run per instance, propagates Stop and reports only real stages. Production calls remain disabled. After initial trials, the per-instance spend ledger is reduced to $1. This is not a deployment-wide limiter, and restarting a process resets it; do not use it as a public-release spend guarantee. No new SEC retrieval, extra agent, storage, export or deployment.

## Live trials, retained failures

All use the public founder-selected E1 question and the frozen source pair with Sol/low. No practitioner, matched ChatGPT or complete E1–E5 release batch was run.

1. Initial browser submit was rejected before model dispatch because Next normalized its internal URL to localhost while the browser used 127.0.0.1. Fixed same-origin validation to compare the actual Host plus protocol; added a regression. A saved brief remained visible after rejection.
2. First paid E1 attempt reached checking, but the takeaway failed reference checks. It did not publish a brief. Detailed provider usage/drop reasons were not retained for this attempt; do not infer its exact failure or exclude it from the record.
3. Instrumented E1 attempt: two completed provider requests (2,788ms / 9,277ms), one tool execution. Usage: input 27,642 / 30,596; output 22 / 421. A finding failed text/fact-reference validation and the dependent takeaway was removed. This does not prove missing company evidence. Added precise content-free drop categories and tightened declared-placeholder instructions/finding-ID enums without weakening checks.
4. Final E1 attempt: first provider completed in 4,113ms (input 27,691; output 93). Second was incomplete after 98,969ms (input 31,346; output 8,192), with one tool execution. No brief was published. The response consumed its full output ceiling; an incomplete response is generation failure, not source limitation. Added a specific safe error code/copy and regression. Do not declare the prompt change successful.

Visible real researching/checking state and honest failed-turn behavior were observed. Paid API trial outputs remain insufficiently reliable; source scope and code checks were retained. The frontend is reviewable through the saved reference, while successful live E1–E4 rendering, E4 CTA revision, real E5 interpretation, browser Stop/late-response races and repeated semantic/control cases remain release gates.
